## Credential provider identity, autofill visibility and phone Settings (2026-10-15)

Root causes, from the AndroidX Credentials 1.6.0 and AOSP sources: `CallingAppInfo` and `SigningInfoCompat` do override `equals()` (package, origin, signers), so the create/query phase comparison was correct and stays. The released APK targets SDK 36 without `<queries>`, and Android's credential selector (not the caller) starts the provider activity, so `PackageManager` usually hid the caller and the caller check threw before any passkey or password operation. Credential Manager now uses Android's supplied signers, still cross-checked against a visible installed package. Autofill fills make the requesting app visible (it starts MYLE for a result); saves do not, so the native plugin declares `<queries>` for launcher apps and HTTPS browsers, and the mobile workflow fails if the merged APK loses them. A browser WebAuthn request without an RP ID uses the origin host; an app must name its RP. MYLE's webview is excluded from autofill, and its own package from Credential Manager.

- Kotlin compilation and JUnit (same pinned classes): 23 passed. New policy tests failed (unresolved) before the implementation.
- `cargo test --manifest-path backend/Cargo.toml --locked --workspace`: 656 passed. The browser default-RP test failed (`badRequest`) before the change.
- `cargo clippy ... -- -D warnings`, `npm run check`, desktop/mobile/setup Vite builds and `node --test "scripts/tests/*.test.mjs"` (310): passed.
- Browser preview (`npx vite --mode mobile`, `?android=30|34`, `?update`) at 360x780 and 320x640: no horizontal overflow; every Settings control at least 48px; Change master password opens over Settings, Escape closes the dialog first and returns focus, then closes Settings.

Not verified: a Gradle-merged APK (CI), and any physical Android 14+ device flow (passkey create/sign-in in Chrome or an app, autofill save, the webview's autofill exclusion).
