## 👀 Compare

- **Click any changed file** to see it: text files side by side or unified (your choice is remembered), with line numbers; an added or deleted file is shown whole.
- **Images** (PNG, JPG, GIF, WebP, ICO, BMP, AVIF, SVG) are shown before and after; small icons are enlarged so a change can be seen, and SVG's source can be shown as text.
- **Other files** show their size and SHA-256 on both sides, and whether the content is the same.
- Files in UTF-16 are read properly, and a file whose only change is CRLF ↔ LF says so instead of showing every line as changed.
- Comparing shows its progress and can be cancelled. Step through the files with **↑ / ↓**, filter with **Ctrl+F**; long lists and long files load as you go.

## 🧹 What is left out

- New names that are never sources: `.next`, `.nuxt`, `.svelte-kit`, `.vite`, `.turbo`, `.angular`, `.expo`, `coverage`, `__pycache__`, `.venv`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `.gradle`, `.dart_tool`, `DerivedData`, `xcuserdata`, `.godot`, `cmake-build-*`, `CMakeFiles`, `*.pdb`, `*.ilk`, editor caches and more.
- Folders that are sometimes sources (`target`, `build`, `bin`, `obj`, `out`, `Debug`, `Release`, `x64`, `packages`, `Pods`, `Library`, `venv`, `gen`, …) are left out **only when they are output**: `Cargo.toml` next to `target`, a `.csproj` next to `bin`/`obj`, `pyvenv.cfg` inside a `venv`, `CMakeCache.txt`, Unity's `Assets` + `ProjectSettings`, a `.gitignore` that lists them, or git tracking nothing in them.
- **What git tracks is always kept**, like an installer's `build\installer.nsh`, and `.env` files are always backed up.
- Your exclusions from 9.4.0 are brought up to date by themselves; patterns you added stay.

## 🧭 Project Backups

- **First-run steps** until your first backup: choose where backups go, add a project, back up.
- **Search** your projects (press **/**), and see on each one whether its last backup worked, failed or was cancelled, and when.
- Progress in plain words: what each step does, step x of 8, files and bytes done.
- A failed backup now comes with the fix: **Start Google Drive**, **Choose the folder again**, **Back up to Dropbox**, **Review exclusions**, **Find the folder** or **Try again**.
- The cloud folder is made ready before your app is closed, so it is never closed for nothing.
- A backup never overwrites a zip of the same name that another program saved meanwhile.
- Unsaved changes in the project editor are confirmed before closing, and resetting the exclusions to the defaults asks first.

## ⚠️ Good to know

- Folders without a marker that git does track stay in the backup; add them under **Also leave out** if you don't want them.
- The page is in English, like the rest of MYLE.
