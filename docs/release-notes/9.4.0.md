## 🗂️ Project Backups

- Backups go to `Projects Backup\<App>\<YYYY-MM Month>\<App>_D<day>_V<n>.zip` in **Google Drive** or **Dropbox**, exactly where backup_projects puts them, so both apps add to one history.
- **Google Drive not running?** MYLE starts it and waits for its drive. Dropbox is started too.
- **What is left out:** `.git`, `node_modules`, `dist`, `release`, `target`, caches, logs and the like, plus anything you add, for all projects or one. `build` is left out only when it is build output. `.env` files are backed up. The editor shows what a backup will hold before you run it.
- **Close an app first** (optional): name its program, and MYLE closes it before the backup. MYLE never closes itself.
- A project whose folder has moved opens its editor on the folder, and the backup carries on once you save.
- Progress for every step, and **Cancel** at any time: nothing half-written is left in your cloud folder.

## 🔍 Compare

- Pick two backups, or a backup and the project folder, and see the **Added**, **Modified** and **Deleted** files with counts and filters.
- Text files open side by side; binary files show their sizes.
- A file that is "deleted" in the newer backup but still in your project folder is pointed out.

## ⚠️ Good to know

- On first start MYLE imports your projects from backup_projects (its `projects.json`, or the copy in Google Drive). **Import** on the page brings in any added later.
- backup_projects keeps working as before; you can use either app.
- This first version backs up when you ask it to; there are no scheduled project backups yet.
