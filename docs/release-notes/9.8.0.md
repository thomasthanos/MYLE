## ✨ Highlights

| | What's new |
|---|---|
| 🔨 **The full build, step by step** | The project's own build script comes first, with its steps listed (for MYLE: app, setup window, uninstaller, payload, setup), each one lighting up as the build reaches it. |
| 🏷️ **Releases that really finish** | In GitHub Actions mode MYLE now follows the release workflow itself, not whichever run on the tag ends first. |
| 📝 **Notes always published** | In GitHub Actions mode, the notes you write or let AI write go into the release commit, so the workflow publishes them with the release. |
| 🧹 **Tags without a release** | A new list in the Releases tab: pick some or all, and delete them on GitHub and on your PC in one go. |

## 🔨 Build

- The project's own top-level build script (`build`, `build-all`, `release`, `dist`, …) is chosen first and labelled as **the project's build**, with the number of steps it runs.
- Its steps are shown in order, from the scripts it chains and the steps of the script file it starts; during a build they tick off one by one.
- `tauri build` is offered on its own only when no script already runs it, and says so when the project has bundling off (it then makes the app alone, with no installer).
- Picked a command that does only part of the build? MYLE shows the full one, with a **Use the full build** button. **Build here, upload** uses the same command and warns the same way.
- When a build makes no files to ship, the page says so.

## 🏷️ Release

- **GitHub Actions mode** follows the run of the release workflow the tag starts. A tag that also starts other workflows (MYLE Passwords, say) no longer makes MYLE call the release done early.
- The **title** defaults to the GitHub repository's name (`MYLE v9.8.0`), not the folder's.
- The **checks** no longer keep spinning while you type: they fetch from GitHub at most every 90 seconds, and only the newest answer is shown.
- With no notes written, the page says GitHub will list the changes since the last release.
- Releasing with **Build here, upload** while a workflow also runs on the tag now shows a warning, since both would publish.

## 📚 Releases tab

- **Tags without a release**, next to the releases, with a count: where each tag is (GitHub, this PC or both) and when it was made.
- Pick one, several or **all**, then **Delete**: the confirmation names every tag, and they are removed on GitHub and on your PC. A tag that a release uses is never deleted this way.

## 🧩 Also in this release

9.7.1 and 9.7.2 never got a GitHub release, so their changes are listed here too:

- **Project Backups**: grouped summaries, a health badge per project (missing, failed, stale, ok), clearer destination and status messages, and a more compact project list.
- **System Cleaner**: shows both the space freed and the space still in use, with live progress; files it could not delete are counted with their size, and the summary includes them.
