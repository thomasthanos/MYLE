## 📁 Projects

- **Add** a repository, or **scan a folder** to find all of them at once. Press **/** to search.
- **Monorepos** show each app as its own project, with its own versions and its own tags (`backup_projects-v2.0.7`); older shared `v…` tags still count as its last release.
- Each project shows its GitHub repository, branch, commits to push or pull, changed files, the versions in every version file (with a warning when they disagree), the last tag and release, the last GitHub Actions run, and what it is built with.
- The sidebar counts the projects that have commits to pull.

## 📝 Changes

- Tick the files that go into the commit (or leave none ticked to commit everything shown); a monorepo app can show only its own files.
- Click a file to see its diff, side by side or in one column, with images shown before and after.
- **Generate with AI** writes the commit message from the diff (lock files left out).
- **Commit**, **Commit & Push** (Ctrl+Enter / Ctrl+Shift+Enter) and **Pull** (rebase, your changes kept). A rejected push, a failed hook, a missing upstream branch, a blocked secret or a missing git name each get a clear message and the button that fixes it.

## 🔨 Build

- The build command is found for you (`build`/`dist`/`release` scripts with npm, pnpm, yarn or bun, Tauri, Cargo, .NET, PyInstaller, Go, Flutter), or type your own.
- A live log with stages and progress (estimated from your last build), and **Cancel** that stops the whole process tree.
- A **Problems** list of errors and warnings from Rust, TypeScript, svelte-check, ESLint, Vite, esbuild, electron-builder, NSIS, MSBuild, Python and Go; click one to open the file at that line in VS Code.
- The installers and update files the build made are listed, with their SHA-256 one click away; full logs are kept on disk.

## 🏷️ Release

- **Patch / Minor / Major** or any version: every version file (package.json, package-lock.json, Cargo.toml and Cargo.lock, tauri.conf.json, pyproject.toml, .csproj, extension manifests) is set at once, with a preview, keeping each file's formatting. Leave out a file with one click.
- **Release notes** by hand, or **Write with AI** from the commits since the last release, and **Polish** what you wrote.
- **Checks** before anything changes: the version, a GitHub remote, the branch up to date, uncommitted changes, the tag still free, your account, the workflow or build command.
- **Build here, upload**: build, commit, push, tag, then a GitHub release with your files uploaded (with progress) and published. Or **GitHub Actions**, picked by itself when a workflow runs on the tag: MYLE pushes the tag and follows the run job by job.
- A failure before the push puts your files back as they were; after it, **Resume** finishes the uploads and publishing.

## 📚 Releases

- Every release of the project with its downloads; **edit** a title or notes, **delete** one or several (their tags too, if you ask).
- **Combine notes**: AI joins several releases' notes into the newest one; deleting the others is a separate question.

## 🔐 GitHub account and AI keys

- MYLE uses your **GitHub CLI** sign-in, or a token you paste. If the GitHub CLI or Git is missing, a button installs it in a window you can see; nothing is installed silently.
- The token and your AI keys are checked, then kept **encrypted for your Windows account**. They never appear on the page again, aren't synced, and git gets the token only for a push or pull (never on a command line or in `.git/config`).
- AI keys are entered in the page's settings. If a provider hits its limit or fails, MYLE offers the next one you set up; it never switches by itself.
- **Github-Build-Release** users: its last project and DeepSeek key come over the first time you open the page, and the plain-text key in its settings file is removed (the page tells you).

## ⚠️ Good to know

- The page needs **Git**. Releases and Actions runs need a **GitHub account** connected in the page.
- AI features need a key: a free **Groq** key from [console.groq.com/keys](https://console.groq.com/keys) is enough. Your diffs and commit messages are sent to the provider you use.
- Sign-in with GitHub in the browser without the GitHub CLI is not available yet.
- The page is in English, like the rest of MYLE.
